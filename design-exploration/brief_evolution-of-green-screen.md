# Venture Studio Aesthetic Explorer  
**Purpose:** Visual exploration, not a production site  
**Type:** Mood board / living UI palette  
**Audience:** Internal team + collaborators  
**Output:** One interactive page with tabs

---

## 1. Context & Design Hypotheses

We are exploring a visual identity for a venture studio that builds many early-stage prototypes. The aesthetic should feel like a **modern evolution of old green-screen / terminal design** without feeling retro, hacker-themed, or crypto-styled.

**Core hypothesis:**  
A restrained, typographic, dark-mode system with selective use of rich green accents can communicate both builder energy and credibility.

### Design Principles
- Green is a **signal**, not a background fill.
- Black is **space**, not emptiness.
- Typography is the primary visual asset.
- Interaction and motion should feel like **system feedback**, not decoration.
- The overall feel should resemble a **tool or workspace**, not a marketing website.

We are intentionally exploring multiple expressions of this same core idea side-by-side to compare how they feel before committing to a brand direction.

---

## 2. What This Is (and Is Not)

**This is:**
- A single-page aesthetic explorer
- A mood board you can browse
- A lightweight, visual decision-making tool
- A place to compare colors, fonts, and basic UI styles

**This is not:**
- A full website
- A CMS or backend-driven product
- A finalized design system
- A marketing funnel

It’s acceptable if this works best on desktop and prioritizes clarity over completeness.

---

## 3. Page Structure (Simple)

### Top of Page
- Page title:  
  **Studio Aesthetic Explorer**
- One short intro sentence explaining this is an exploration tool.

### Primary Interaction
A row of tabs across the top. Switching tabs updates the visual styling of the same content.

Tabs:
- Editorial
- System
- Expressive
- Minimal

Only one tab visible at a time.

---

## 4. What Each Tab Shows

Each tab presents the **same sections**, styled differently. This allows direct comparison.

---

### Section A: Hero Snapshot

A simple hero-style block used to test tone and hierarchy.

**Content (same in all tabs):**
- Headline:  
  *We build ideas until they work.*
- Short subline (1 sentence)
- Two buttons:
  - Primary
  - Secondary

Used to explore:
- Type scale
- Weight
- Color usage
- Overall mood

---

### Section B: Color Palette

A small grid of color swatches showing:
- Primary background color
- Primary text color
- Accent green(s)
- Optional secondary accent

Each swatch should display:
- Color block
- Hex code
- Short label (e.g. “Accent Green”)

This is about feel, not precision.

---

### Section C: Typography Pairing

Display the fonts used in this tab:
- Headline font
- Body font
- Optional mono / utility font

Each font shown with:
- A sample headline
- A short paragraph
- Small metadata-style labels

The goal is to feel the personality of the typography.

---

### Section D: UI Elements

A small set of example UI components:
- Primary button
- Secondary button
- Text link
- Tag or badge
- Divider or rule

Only basic hover states are needed.

## 5. Tab Mood Definitions

### Editorial
**Mood:** Calm, confident, premium  
**Feel:** Design studio meets editorial layout  
- More whitespace
- Softer contrast
- Green used sparingly
- Typography does most of the work

This is the “credible and composed” option.

---

### System
**Mood:** Builder energy, terminal lineage  
**Feel:** Modern system console  
- Darker background
- More mono usage
- Green used for dividers, highlights, state
- Slightly denser layout

This nods to green-screen heritage without retro styling.

---

### Expressive
**Mood:** Playful, kinetic, future-facing  
**Feel:** Prototype lab  
- Bolder type
- Brighter or more frequent green accents
- Looser layout
- More contrast

This is where experimentation and motion are allowed.

---

### Minimal
**Mood:** Extreme restraint  
**Feel:** Confidence through absence  
- Near-monochrome
- Minimal green
- Strong focus on spacing and type

This acts as a control sample.

---

## 6. Motion & Interaction Guidance

- Motion should feel like **system feedback**
- No looping or decorative animation
- Tab switches should be subtle and fast
- Cursor or terminal references should be minimal and restrained

---

## 7. Success Criteria

This prototype is successful if:
- Switching tabs immediately changes the emotional tone
- You can intuitively say “this feels closer” or “this doesn’t”
- It sparks discussion rather than decisions
- It becomes a shared reference point for next steps

---

## 8. Build Intent (for Codex)

The goal is to **quickly prototype a single-page aesthetic explorer**.  
Prioritize:
- Visual clarity
- Contrast between tabs
- Clean typography
- Ease of iteration

Technical completeness is less important than expressive clarity.
